Master’s thesis research

Assessing Municipal Building Data for Urban Digital Twin Readiness

This thesis investigates whether an existing authoritative municipal building dataset can support the requirements of 3D city modelling and Urban Digital Twin frameworks.

The research focuses on the CSI building dataset of Turin, with Circoscrizione 7 as the study area and the Lavazza building as a detailed object-level case study. The work evaluates geometric completeness, height availability, Level of Detail potential, semantic structure, and interoperability limitations.

Research contribution

  • Dataset-level assessment of height availability and 3D readiness.
  • Object-level validation using the Lavazza building case study.
  • Identification of fragmentation and weak entity relationships.
  • FIWARE-inspired restructuring from GIS layers to Building + BuildingPart entities.

Methodological workflow

From GIS inspection to UDT-oriented restructuring

The workflow tests the dataset at two scales: the full Circoscrizione 7 dataset and the Lavazza building as a detailed case study.

1. Data preparation QGIS
  • Inspection of CSI building layers
  • Filtering of Circoscrizione 7
  • Creation of height and quality indicators
2. Model validation 3D
  • 2D height map generation
  • 3D extrusion using height attributes
  • Consistency checks of geometry and height values
3. Entity restructuring FIWARE
  • Building entity definition
  • BuildingPart entities for volumetric units
  • Explicit hasPart relationship

Transformation logic
1. Preserve geometric partsDo not merge polygons into one height value.
2. Standardize attributesUse building_id, part_id, height_m, floors, and part_type.
3. Add explicit relationshipsConnect all parts to Lavazza_B1 using hasPart.
4. Improve UDT readinessMove from isolated shapes to a connected urban object model.
SQL-style relational structure
CREATE TABLE Building (
  building_id VARCHAR PRIMARY KEY,
  name VARCHAR,
  use_type VARCHAR,
  construction_year INT
);

CREATE TABLE BuildingPart (
  part_id VARCHAR PRIMARY KEY,
  building_id VARCHAR,
  height_m FLOAT,
  floors INT,
  surface_area FLOAT,
  part_type VARCHAR,
  geometry GEOMETRY,
  FOREIGN KEY (building_id)
    REFERENCES Building(building_id)
);

Synthesis

Findings and proposed improvements

The case study shows that the CSI dataset contains useful geometric information, but its current structure limits direct use in Urban Digital Twin environments.

Before: GIS layer structure

  • One real building represented as several polygons.
  • Different heights stored separately.
  • No explicit connection between parts.
  • Limited object-level coherence.
  • Useful for mapping, weaker for UDT integration.

After: FIWARE-inspired structure

  • One Building entity.
  • Six connected BuildingPart entities.
  • Height variation preserved.
  • Explicit hasPart relationship.
  • Closer to interoperable Urban Digital Twin logic.
Final interpretation

The dataset is geometrically rich but structurally fragmented. It can support basic 3D visualization, but it is not directly organized for Urban Digital Twin integration.

The FIWARE-oriented restructuring improves the dataset by preserving the original geometry while introducing explicit entities, attributes, and relationships.
