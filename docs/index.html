Master’s thesis research output

Assessing Municipal Building Data for Urban Digital Twin Readiness

This research evaluates whether existing municipal GIS building data can support a transformation path toward 3D city modelling, spatial database representation, and future Urban Digital Twin interoperability.

The workflow moves from institutional geodata context to QGIS-based readiness assessment, Building/BuildingPart reconstruction, PostGIS relational storage, GeoJSON and NGSI-LD-style outputs, and interactive 3D visualization.

Main contribution

  • Multi-scale dataset-readiness assessment.
  • QGIS processing and 3D validation of municipal building data.
  • Building/BuildingPart reconstruction of fragmented geometries.
  • PostGIS relational prototype for queryable and scalable output.
  • GeoJSON and NGSI-LD-style export for future UDT interoperability.

Transformation path

Continuous standard-oriented workflow

The thesis output is not only a 3D model. It is a structured transformation workflow connecting GIS data, 3D city modelling logic, spatial database representation, and future UDT-oriented interoperability.

1

Institutional context

BDTRE and regional geodata frame provenance, coverage, and official data context.

2

QGIS processing

CSI layers are filtered, cleaned, inspected, and prepared for district and building analysis.

3

3D readiness

Height availability and LoD1-like extrusion potential are evaluated.

4

Object reconstruction

Fragmented polygons are reorganized as BuildingPart components of one Building.

5

PostGIS model

The reconstructed structure is stored as queryable relational spatial tables.

6

UDT outputs

GeoJSON, NGSI-LD-style JSON, and interactive 3D outputs communicate the result.

Database representation

PostGIS relational prototype

PostGIS is used to demonstrate that the reconstructed Building/BuildingPart logic can be stored as a spatial relational model, queried, related, and exported.

Relational schema
CREATE TABLE building (
  building_id VARCHAR(50) PRIMARY KEY,
  name VARCHAR(100),
  building_use VARCHAR(100),
  ngsi_entity VARCHAR(150)
);

CREATE TABLE building_part (
  part_id VARCHAR(50) PRIMARY KEY,
  building_id VARCHAR(50),
  height_m NUMERIC,
  num_floors INTEGER,
  part_type VARCHAR(50),
  lod_potential VARCHAR(50),
  quality_flag VARCHAR(50),
  ngsi_entity VARCHAR(150),
  relationship VARCHAR(50),
  partOf VARCHAR(150),
  geom geometry(Polygon, 4326),
  FOREIGN KEY (building_id)
    REFERENCES building(building_id)
);
SQL validation query
SELECT 
  b.building_id,
  b.name,
  p.part_id,
  p.height_m,
  p.part_type,
  p.lod_potential,
  p.ngsi_entity
FROM building b
JOIN building_part p
ON b.building_id = p.building_id
WHERE b.building_id = 'Lavazza_B1'
ORDER BY p.height_m DESC;

Synthesis

Findings and proposed improvements

The thesis shows that the dataset has clear potential, but it requires evaluation, reconstruction, and database-oriented structuring before it can support standard-oriented reuse.

Before: municipal GIS structure

  • Layer-based organization.
  • Fragmented building representation.
  • Incomplete height information for some features.
  • Weak parent-child object relationships.
  • No ready database schema for UDT-oriented use.

After: reconstructed output

  • One parent Building object.
  • Six linked BuildingPart records.
  • PostGIS relational storage.
  • SQL validation and queryability.
  • GeoJSON / NGSI-LD-style export and clickable 3D visualization.
PostGIS-based interactive 3D reconstruction of Lavazza
Interactive 3D model generated from the reconstructed PostGIS BuildingPart layer. Each component remains clickable and linked to attributes such as part_id, height_m, part_type, ngsi_entity, relationship, and partOf.
Final interpretation

The final prototype demonstrates that fragmented GIS building geometries can be transformed into a structured and queryable object model. This supports the transition from conventional GIS layers toward standard-oriented 3D city modelling and future Urban Digital Twin interoperability.
